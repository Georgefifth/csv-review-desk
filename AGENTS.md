# CSV Review Desk

Improve the existing static product using verified workflow evidence. Research competitors publicly; do not inspect, scan or reuse sibling projects or unrelated local files.

Keep the interface, error messages and current documentation in English. Preserve original source strings and rows. Never infer ambiguous dates, invent missing facts, merge duplicates or discard rows automatically. Changes need clear previews or explicit edits; exclusions need reasons and audit records.

Architecture: static HTML/CSS, JavaScript modules, vendored Papa Parse 5.7.0. No backend, analytics, remote fonts, accounts, automatic persistence or AI calls. Keep relative asset paths compatible with GitHub Pages.

Projects contain sensitive user data. Save only on explicit action; validate structure and bounds on restore. No arbitrary code from JSON. Never publish working files, captures, credentials or local research notes. The deployment build must use an explicit file allowlist.

Run `node core.test.mjs`, `node project.test.mjs`, and `node --check app.mjs` for material changes. Verify file selection, issue repair, undo, resume, stale export prevention and mobile layout in the browser. Test the actual public release after deployment.

Separate observed results, documented competitor claims and assumptions. Do not call synthetic task tests market validation. Avoid feature additions without a concrete task benefit and acceptance condition.
